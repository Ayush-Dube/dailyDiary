📌 1. My Situation

✅ I have one Flask project.
✅ Everything was initially written in one file (app.py).
✅ I have already made around 10 commits.
✅ All commits are pushed to GitHub on the main branch.

Current Structure

main
│
├── Commit 1
├── Commit 2
├── Commit 3
├── ...
└── Commit 10


------------------------------------------------------------

📌 2. My Intent

🤔 I don't want to delete my old code.

Instead, I want to:

✨ Keep Version 1 forever.
✨ Create a completely different Version 2.
✨ Maybe create Version 3 later.
✨ Maybe Version 4 later.

Every version may have:

✅ Different folder structure
✅ Different architecture
✅ Different code
✅ Different files

Even if I delete everything and rewrite from scratch,
I still want the previous versions to remain safe.

This is exactly what Git Branches are made for.

------------------------------------------------------------

📌 3. Correct Solution

🌿 Create a new branch.

Example

git checkout main

git checkout -b v2-rewrite


Now I'm inside

🌿 v2-rewrite

NOT

🌳 main

------------------------------------------------------------

📌 4. What can I do now?

Inside v2-rewrite I can...

🗑 Delete every file

📁 Create new folders

📄 Create new files

🧠 Rewrite everything

⚡ Change architecture

🔄 Start from zero

There are NO restrictions.

Why?

Because I'm NOT touching main.

------------------------------------------------------------

📌 5. Commit Normally

git add .

git commit -m "Rewrite project"

------------------------------------------------------------

📌 6. Push Normally

git push origin v2-rewrite

Done ✅

Now GitHub contains

🌳 main
🌿 v2-rewrite

Both are independent.

------------------------------------------------------------

📌 7. Future

If another idea comes...

😁 "Meri phir se khujli hui."

Create another branch.

git checkout main

git checkout -b v3-experimental

or

git checkout v2-rewrite

git checkout -b v3-clean

Now start another version.

------------------------------------------------------------

📌 8. Final Repository

Repository

🌳 main
│
├── Version 1 (Original Project)
│
├── 🌿 v2-rewrite
│      Completely rewritten
│
├── 🌿 v3-clean
│      Better architecture
│
└── 🌿 v4-fastapi
       FastAPI version

All versions stay forever.

------------------------------------------------------------

📌 9. Branch Rule

Whenever I'm on a branch

👇

1️⃣ Make changes

2️⃣ git add .

3️⃣ git commit

4️⃣ git push origin <same-branch>

Example

If I'm on

🌿 main

↓

git commit

↓

git push origin main

-----------------------------

If I'm on

🌿 v2-rewrite

↓

git commit

↓

git push origin v2-rewrite

-----------------------------

If I'm on

🌿 feature-auth

↓

git commit

↓

git push origin feature-auth

✅ Commit and Push should normally happen on the SAME branch.

------------------------------------------------------------

📌 10. Branch Switching

Switch to old version

git checkout main

Now my project becomes

📁 Version 1

-----------------------------

Switch to rewritten version

git checkout v2-rewrite

Now my project instantly becomes

📁 Version 2

Git automatically changes all files.

No copy-paste needed.

------------------------------------------------------------

📌 11. Biggest Beginner Mistake ❌

Don't do this

app.py
app_new.py
app_final.py
app_latest.py
app_final_final.py
app_real_final.py

😵 This becomes impossible to manage.

Instead

🌳 main
🌿 v2
🌿 v3
🌿 v4

Git manages versions for me.

------------------------------------------------------------

📌 12. My Personal Workflow 🚀

① Build first version on main.

② Commit regularly.

③ Push regularly.

④ When I want a completely different version:

    git checkout main
    git checkout -b new-version

⑤ Rewrite anything I want.

⑥ Commit.

⑦ Push.

⑧ Repeat whenever I get a new idea.

------------------------------------------------------------

📌 13. Golden Rule ⭐

🌳 main
=
Stable version.

🌿 Other branches
=
Experiments, rewrites, new ideas.

Never fear deleting or rewriting code inside another branch.

Your old work always remains safe in main.

Git was literally designed for this purpose.

╔══════════════════════════════════════════════════════════════╗
║          🐍 PYTHON IMPORTS - ONE PAGE CHEAT SHEET           ║

1️⃣ Every .py file = MODULE 📦

project/
├── app.py
├── database.py
└── aircraft.py

--------------------------------------------------------------

2️⃣ import module 📦
--------------------

import database

database.get_db_connection()

✅ Rule:
module.function()

--------------------------------------------------------------

3️⃣ from module import function 🎯
---------------------------------

from database import get_db_connection

get_db_connection()

✅ Rule:
function()

--------------------------------------------------------------

4️⃣ import module as alias ✨
----------------------------

import database as db

db.get_db_connection()

✅ Rule:
alias.function()

--------------------------------------------------------------

5️⃣ from module import * ⚠️
---------------------------

from database import *

get_db_connection()

❌ Avoid in real projects
Reason:
- Namespace pollution
- Function conflicts
- Hard to debug

--------------------------------------------------------------

6️⃣ Multiple Functions 📚
-------------------------

from database import get_db_connection, insert_data

get_db_connection()
insert_data()

--------------------------------------------------------------

7️⃣ Same Function Names 🚨
--------------------------

database.py  -> connect()
mysql.py     -> connect()

❌ Bad

from database import *
from mysql import *

connect()   ← Which one?

✅ Good

import database
import mysql

database.connect()
mysql.connect()

--------------------------------------------------------------

8️⃣ Real Flask Example 🌐
-------------------------

database.py

def get_db_connection():
    ...

aircraft.py

import database

def get_all_aircraft():
    conn = database.get_db_connection()

app.py

import aircraft

aircraft.get_all_aircraft()

--------------------------------------------------------------

9️⃣ GOLDEN RULES ⭐
------------------

import module
    ➜ module.function()

from module import function
    ➜ function()

import module as m
    ➜ m.function()

from module import *
    ➜ function()   (Avoid)

--------------------------------------------------------------

🔟 Industry Recommendation 💼
------------------------------

✅ Small Project
from database import get_db_connection

✅ Large Project (Preferred)
import database

database.get_db_connection()

Reason:
✔ Readable
✔ Easy Debugging
✔ No Name Conflicts

═══════════════════════════════════════════════════════════════

🧠 MEMORY TRICK

📦 import database
   → Bring the WHOLE cupboard
   → database.function()

🎯 from database import function
   → Bring ONLY one drawer
   → function()

═══════════════════════════════════════════════════════════════
```

```


╔══════════════════════════════════════════════════════════════════════════╗
║ 🐍 PYTHON DICTIONARY → FLASK → DYNAMIC SQL FILTERING                     ║
╚══════════════════════════════════════════════════════════════════════════╝

1️⃣ DICTIONARY BASICS
│
├── 1.1 Dictionary kya hai?
│      └── key → value mapping
│
│      user = {
│          "name": "Rahul",
│          "age": 22,
│          "city": "Bangalore"
│      }
│
│      "name"  → key
│      "Rahul" → value
│
├── 1.2 Access
│      └── user["name"]        → "Rahul"
│      └── user.get("name")    → "Rahul"
│
├── 1.3 Missing key
│      └── user["email"]       → KeyError
│      └── user.get("email")   → None
│
├── 1.4 Add / Update
│      └── user["city"] = "Delhi"
│
│      key exists     → value UPDATE
│      key doesn't    → new pair INSERT
│
├── 1.5 Delete
│      └── del user["age"]
│      └── user.pop("age")
│
└── 1.6 Useful operations
       ├── len(user)              → number of pairs
       ├── "name" in user         → key exists?
       ├── user.keys()            → keys
       ├── user.values()          → values
       ├── user.items()           → key-value pairs
       └── user.update({...})     → multiple add/update


2️⃣ DICTIONARY TRAVERSING 🔄
│
├── 2.1 Direct loop
│      └── for i in user:
│
│      i gets KEYS
│
│      name
│      age
│      city
│
├── 2.2 Values traverse
│      └── for i in user.values():
│
│      i gets VALUES
│
│      Rahul
│      22
│      Bangalore
│
├── 2.3 Key + value traverse
│      └── for key, value in user.items():
│
│      key   = "name"       value = "Rahul"
│      key   = "age"        value = 22
│      key   = "city"       value = "Bangalore"
│
└── 2.4 IMPORTANT MEMORY TRICK 🧠
       ┌───────────────────────────────────────┐
       │ for x in list          → elements     │
       │ for x in dict          → keys         │
       │ for x in dict.values()  → values       │
       │ for k,v in dict.items() → both         │
       └───────────────────────────────────────┘


3️⃣ LIST vs DICTIONARY 🔄
│
├── List
│
│      arr = [10, 20, 30]
│
│      for i in arr:
│          print(i)
│
│      i → 10 → 20 → 30
│
└── Dictionary
       user = {
           "name": "Rahul",
           "age": 22
       }
       
       for i in user:
           print(i)

       i → "name" → "age"

       ⚠️ Dictionary mein direct iteration KEYS par hoti hai.


4️⃣ .items() KO DEEPLY SAMJHO 🔍
│
├── user.items()
│
│      roughly gives:
│
│      ("name", "Rahul")
│      ("age", 22)
│
├── Python unpacking:
│
│      pair = ("name", "Rahul")
│
│      key, value = pair
│
│      key   → "name"
│      value → "Rahul"
│
└── Therefore:
       
       for key, value in user.items():

       ka matlab:

       "har key-value pair ko ek-ek karke lo
        aur key/value variables mein unpack karo."


5️⃣ DICTIONARY PROTECTION 🔒
│
├── Normal dict:
│
│      user["age"] = 25
│
│      ✅ value change ho sakti hai
│
├── Normal dict mein built-in "read-only key/value"
│   declaration nahi hota.
│
└── Read-only VIEW:
       
       from types import MappingProxyType
       
       readonly_user = MappingProxyType(user)

       readonly_user["age"] = 25
       ❌ Error

       ⚠️ MappingProxyType = read-only VIEW,
          completely immutable dict nahi.


6️⃣ NESTED DATA 🪆
│
├── Dict inside dict
│
│      user = {
│          "name": "Rahul",
│          "address": {
│              "city": "Bangalore",
│              "pincode": 560001
│          }
│      }
│
│      user["address"]["city"]
│      → Bangalore
│
├── List inside dict
│
│      user = {
│          "name": "Rahul",
│          "skills": ["Python", "Flask", "SQL"]
│      }
│
│      user["skills"][0]
│      → Python
│
└── Dicts inside list
       
       users = [
           {"name": "Rahul", "age": 22},
           {"name": "Amit", "age": 25}
       ]

       for user in users:
           print(user["name"])


7️⃣ FLASK REQUEST OBJECT 🌐
│
├── request
│      └── Flask ka request OBJECT
│
├── request.args
│      └── URL ke query parameters
│
│      /products?name=iphone&brand=apple
│
│      request.args
│      ≈
│      {
│          "name": "iphone",
│          "brand": "apple"
│      }
│
│      ⚠️ Technically request.args = MultiDict
│
└── request.args.items()
       └── key-value pairs


8️⃣ FLASK QUERY PARAMETERS TRAVERSING 🔄
│
│   URL:
│   /products?name=iphone&brand=apple
│
│   request.args.items()
│
│   ↓
│
│   ("name", "iphone")
│   ("brand", "apple")
│
│   ↓
│
│   for key, value in request.args.items():
│
│   1st iteration:
│       key   = "name"
│       value = "iphone"
│
│   2nd iteration:
│       key   = "brand"
│       value = "apple"


9️⃣ DYNAMIC FILTERING 🎯
│
├── Problem:
│
│   Kabhi API mein:
│
│      ?name=iphone
│
│   Kabhi:
│
│      ?name=iphone&brand=apple
│
│   Kabhi:
│
│      ?brand=apple&category=mobile&min_price=30000
│
│   Kabhi 11 parameters.
│
│   ❌ Har possible combination ke liye
│      alag code nahi likhna.
│
└── Solution:
       Request parameters ko LOOP karo
       aur dynamically query conditions banao.


🔟 DYNAMIC SQL QUERY BUILDING 🏗️
│
├── Step 1: data lo
│
│      data = request.args
│
├── Step 2: empty lists
│
│      filters = []
│      conditions = []
│
├── Step 3: parameters traverse
│
│      for key, value in data.items():
│          filters.append(f"{key} = ?")
│          conditions.append(value)
│
├── Example request:
│
│      /products?name=iphone&brand=apple
│
├── filters:
│
│      [
│          "name = ?",
│          "brand = ?"
│      ]
│
└── conditions:
       
       [
           "iphone",
           "apple"
       ]


1️⃣1️⃣ SQL QUERY CREATE KARNA 🗄️
│
├── Base query:
│
│      query = "SELECT * FROM someDB"
│
├── Filters ko join:
│
│      " AND ".join(filters)
│
│      ↓
│
│      "name = ? AND brand = ?"
│
├── Final:
│
│      if filters:
│          query += " WHERE " + " AND ".join(filters)
│
└── Result:
       
       SELECT * FROM someDB
       WHERE name = ?
       AND brand = ?


1️⃣2️⃣ `if filters:` KA MATLAB 🧠
│
├── filters = []
│      └── False
│
├── filters = ["name = ?"]
│      └── True
│
└── Therefore:
       
       if filters:

       ≈

       if len(filters) > 0:

       Meaning:
       "Agar filters empty nahi hain."


1️⃣3️⃣ WHY `if filters` IMPORTANT? ⚠️
│
├── User:
│      /products
│
├── filters:
│      []
│
├── Agar blindly:
│
│      query += " WHERE " + " AND ".join(filters)
│
│   toh:
│
│      SELECT * FROM someDB WHERE
│
│   ❌ Invalid / unwanted query
│
└── Therefore:
       
       if filters:
           query += " WHERE " + " AND ".join(filters)

       No filters → WHERE nahi lagega.


1️⃣4️⃣ PARAMETERIZED QUERY 🔐
│
├── ❌ BAD
│
│      query += f" WHERE name = '{value}'"
│
│
├── ✅ GOOD
│
│      filters.append("name = ?")
│      conditions.append(value)
│
│      cursor.execute(query, conditions)
│
└── Why?
       
       User data ko SQL string mein directly
       concatenate nahi karna.

       ? = placeholder

       conditions = actual values

       This helps prevent SQL injection.


1️⃣5️⃣ VERY IMPORTANT SECURITY ISSUE 🚨
│
├── This is NOT enough:
│
│      filters.append(f"{key} = ?")
│
├── Why?
│
│      key bhi user ke URL se aa rahi hai.
│
│      /products?some_random_column=abc
│
│      User arbitrary column inject kar sakta hai.
│
└── Solution: WHITELIST allowed columns ✅
       
       allowed_filters = {
           "name": "name",
           "brand": "brand",
           "category": "category",
           "price": "price"
       }

       for key, value in data.items():

           if key not in allowed_filters:
               continue

           filters.append(
               f"{allowed_filters[key]} = ?"
           )

           conditions.append(value)


1️⃣6️⃣ COMPLETE MENTAL MODEL 🧠🔥
│
│   CLIENT
│      │
│      │ GET /products?brand=apple&category=mobile
│      ↓
│   FLASK
│      │
│      ↓
│   request.args
│      │
│      ↓
│   for key, value in request.args.items()
│      │
│      ├── brand → apple
│      │
│      └── category → mobile
│      │
│      ↓
│   CHECK ALLOWED FILTERS
│      │
│      ↓
│   filters = [
│       "brand = ?",
│       "category = ?"
│   ]
│      │
│      ↓
│   conditions = [
│       "apple",
│       "mobile"
│   ]
│      │
│      ↓
│   SELECT * FROM products
│   WHERE brand = ?
│   AND category = ?
│      │
│      ↓
│   DATABASE
│      │
│      ↓
│   FILTERED RESULTS
│
└──────────────────────────────────────────────────────────────────────────┘


⭐ MOST IMPORTANT 8 THINGS TO REMEMBER
│
├── 1. dict = key → value
├── 2. for x in dict → keys
├── 3. dict.values() → values
├── 4. dict.items() → key + value pairs
├── 5. request.args → URL query parameters
├── 6. request.args.items() → parameters traverse
├── 7. filters + conditions → dynamic SQL
└── 8. SQL values → parameterize with `?`
                         BUT
       SQL column names → whitelist/validate them 🔐
